# 00 — Roadmap & วิธีเรียน

## เป้าหมายของหลักสูตรนี้

ไม่ใช่แค่ "เขียน Next.js ได้" แต่คือ

1. **เข้าใจว่าโค้ดแต่ละบรรทัดรันที่ไหน เมื่อไหร่** (server? browser? ตอน build? ตอน request?)
   — ถ้าตอบคำถามนี้ได้ทุกบรรทัด คุณเข้าใจ Next.js แล้ว 80%
2. **คิดเป็นระบบ** — เห็นโจทย์แล้วแตกเป็น data → route → component → boundary ได้ก่อนเขียนโค้ด
3. **ส่งของขึ้น production ได้อย่างมั่นใจ** — มีเทสต์ มี CI ตรวจให้ มี CD ส่งขึ้นให้

## วิธีเรียนที่ได้ผล

1. **อ่านบท → เปิดไฟล์ที่บทอ้างถึง → รันดู → แก้ให้พัง → แก้ให้หาย**
   การทำให้พังเองเป็นวิธีที่เร็วที่สุดในการเข้าใจว่า "ทำไมต้องเขียนแบบนี้"
2. **ทำแบบฝึกหัดท้ายบทเสมอ** — ความรู้ที่ไม่ได้ลงมือจะหายภายในสัปดาห์
3. **เขียนสรุปด้วยคำพูดตัวเอง** 3–5 บรรทัดต่อบท ถ้าอธิบายไม่ได้ = ยังไม่เข้าใจ
4. **ใช้ git ทุกการทดลอง**: `git switch -c try/xxx` → ลองอะไรก็ได้ → `git switch main` กลับมาปลอดภัย
5. **อ่าน error ให้จบ** — Next.js 16 เขียน error message ดีมาก มักบอกวิธีแก้มาให้เลย
   (ดูตัวอย่างจริงใน [บท 07](07-caching-and-rendering.md#กรณีศึกษาจริง-build-พังเพราะ-usepathname))

## Capstone Project (หลังจบทุกบท)

สร้าง **"Reading Tracker"** ใหม่ตั้งแต่ศูนย์ ใน repo ใหม่ของคุณเอง

- หน้า `/books` รายการหนังสือ, `/books/[id]` รายละเอียด, `/books/new` เพิ่มหนังสือ
- ข้อมูล: ชื่อ, ผู้แต่ง, สถานะ (อยากอ่าน/กำลังอ่าน/อ่านจบ), คะแนน 1–5
- ใช้ database จริง (เช่น SQLite + Drizzle หรือ Postgres ฟรีจาก Neon/Supabase)
- มี filter ด้วย `searchParams` (`/books?status=reading`)
- Unit test ครอบ validation + logic, E2E ครอบ flow หลัก
- CI เขียว + deploy ขึ้น Vercel หรือ Docker

ถ้าทำได้ทั้งหมดนี้ **โดยไม่ต้อง copy จาก repo นี้** = คุณผ่านแล้ว
